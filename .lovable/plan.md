

## План: розсилка повідомлень Telegram кільком отримувачам

### Причина проблеми

В обох edge-функціях (`send-order-telegram` і `create-checkout-session`) chat_id жорстко прописаний:

```ts
const CHAT_ID = 190824720;  // твій особистий ID
```

Telegram-бот не "розсилає всім, хто його додав" автоматично — для кожного отримувача треба окремо викликати `sendMessage` з його `chat_id`. Бот не знає, хто його додав, поки людина не напише йому першою.

### Як це працює в Telegram (важливо розуміти)

1. Кожна людина / група / канал має унікальний `chat_id`
2. Щоб бот міг писати людині — людина має **спочатку написати боту** (хоча б `/start`)
3. Бот отримує `chat_id` з вхідного повідомлення через `getUpdates`
4. Тільки після цього бот може слати їй повідомлення

**Альтернатива (простіше)**: створити груповий чат, додати бота, і слати в групу — всі учасники бачать.

### Рекомендую: варіант з груповим чатом

Найпростіше і найнадійніше для B2B-команди:

1. Створи Telegram-групу "Nokari Orders"
2. Додай туди свого бота + всіх, кому треба бачити заявки
3. Дай боту права адміна (щоб міг писати)
4. Дізнайся `chat_id` групи (від'ємне число типу `-1001234567890`) — я додам тимчасовий лог в функцію, ти напишеш в групу будь-що, я заберу ID з логів і пропишу
5. Замінюємо один `CHAT_ID` на ID групи — все продовжує працювати, але бачать всі

**Плюси**: одне місце, історія в одному чаті, прості права, можна обговорювати замовлення прямо там.

### Альтернатива: список chat_id у env-змінній

Якщо групу не хочеш, а хочеш слати в кілька **особистих чатів**:

1. Кожен отримувач має написати боту `/start`
2. Збираємо їхні `chat_id` (теж через лог `getUpdates`)
3. Зберігаємо як секрет `TELEGRAM_CHAT_IDS` = `190824720,123456789,987654321`
4. У функції парсимо рядок і робимо `sendMessage` в циклі для кожного

**Мінус**: повідомлення дублюються N разів, кожен бачить тільки в себе, нема спільного обговорення.

### Третій варіант (найгнучкіший, але важчий): таблиця підписників

Створити в БД таблицю `telegram_subscribers (chat_id, name, active)`, окрему функцію-поллер, яка слухає `/start` від нових людей і додає їх в таблицю. Функція замовлення читає таблицю і шле всім активним.

**Коли треба**: якщо отримувачів буде багато і список змінюватиметься часто. Для 2-5 людей — overkill.

### Що пропоную зробити

**Крок 1 (зараз)**: вибери один з варіантів вище — груповий чат / список ID / таблиця підписників.

**Крок 2**: я додам тимчасове логування `chat.id` всіх вхідних повідомлень в edge-функцію, ти напишеш боту (або в групу), ми побачимо ID в логах.

**Крок 3**: пропишу ID(ів) у код / секрет, оновлю обидві функції (`send-order-telegram` + `create-checkout-session`), приберу тимчасовий лог.
